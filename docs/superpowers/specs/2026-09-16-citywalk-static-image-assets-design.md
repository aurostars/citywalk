# 城迹静态图片资源设计说明

日期：2026-09-16

## 1. 问题与目标

当前首页主视觉和 8 个活动封面在浏览器运行时直接请求文生图接口。该接口对未认证的公开请求返回 `Authentication failed`，随后重定向到统一的 `default.jpeg` 生成中占位图。由于占位图本身是合法 JPEG，现有 `onError` 回退逻辑不会触发。

本次目标是让 GitHub Pages 上的每个核心图片位稳定展示与内容对应的真实图片，并消除公开页面对文生图接口可用性、认证状态和生成耗时的依赖。

## 2. 范围

### 包含

- 首页主视觉 1 张。
- 8 个北京活动各自独立的封面图。
- 图片静态化、尺寸优化和清晰的文件命名。
- 图片数据引用迁移。
- 加载失败回退与自动化资源验收。
- 桌面端和移动端的图片裁切检查。

### 不包含

- 修改活动内容、推荐排序或页面信息架构。
- 新增图片上传、远程图片管理或后端服务。
- 为每个活动增加多图轮播。
- 改动现有城市杂志视觉方向。

## 3. 资源策略

- 图片在开发阶段完成生成或选定后固化到 `public/images/`，运行时只读取同源静态资源。
- 资源分为 `hero/` 和 `activities/` 两组，文件名使用对应场景或活动 ID。
- 图片统一输出为 WebP，活动图使用 4:3 横图，首页主视觉使用兼容现有容器的 4:3 横图。
- 每张图都必须是独立内容，不得复用统一占位图，不得含可见水印、生成提示或无关文字。
- 图片风格保持真实北京城市生活编辑摄影：自然光、可信地点特征、年轻大学生语境、低饱和自然色。
- 单张图片目标体积不超过 450 KB；在不明显损失界面文字或建筑细节的前提下优先控制在 250 KB 内。
- 已固化资源由 GitHub Pages 直接发布，不在客户端携带图片生成服务凭据。

## 4. 场景清单

1. 首页：北京大学生周末城市探索，作为第一视口主视觉。
2. 798 艺术区：红砖工业建筑与当代艺术空间。
3. 鼓楼市集：胡同街巷、摊位与周末人群。
4. 亮马河演出：夜间滨水、小型现场音乐与观众。
5. 国家大剧院：蓝调时刻、倒影与入场人群。
6. 潘家园市集：旧物、书籍与早间摊位。
7. 首钢园展览：工业遗产、现代展陈与访客。
8. 香山徒步：秋季山路、石阶与年轻徒步者。
9. 温榆河骑行：湿地绿道、开阔天空与骑行者。

## 5. 代码与数据

- `src/data/activities.ts` 的 `imageUrl` 改为 `/citywalk/images/activities/<activity-id>.webp`，与 Vite 的 GitHub Pages `base` 保持一致。
- `src/features/home/HomePage.tsx` 的首页主视觉改为 `/citywalk/images/hero/beijing-weekend.webp`。
- 图片路径通过一个小型资源路径辅助函数生成，避免测试环境和未来部署路径调整时散落硬编码。
- `ImageWithFallback` 保留尺寸占位和错误回退；本次不增加轮询、重试或运行时下载逻辑。

## 6. 错误处理

- 文件请求失败时继续显示现有文字回退，不影响活动信息和操作入口。
- 构建前通过测试检查所有数据引用均指向存在的静态文件。
- 测试检查图片可以解码、宽高符合约定，并且不同活动文件内容哈希不同。
- 禁止把文生图接口的 `default.jpeg` 或其已知哈希作为静态资源提交。

## 7. 验收标准

- 首页与 8 个活动图片均可在断网或阻断文生图域名时正常展示。
- 所有 9 张图片的自然宽高均大于零，且活动图片保持 4:3 展示框不发生布局偏移。
- 9 张图片内容哈希互不相同。
- 页面不再发起 `copilot-cn.bytedance.net/api/ide/v1/text_to_image` 请求。
- 桌面 1440x900 与移动 390x844 下图片裁切合理，无关键主体被明显截断。
- Vitest、生产构建和 Playwright 核心流程全部通过。
