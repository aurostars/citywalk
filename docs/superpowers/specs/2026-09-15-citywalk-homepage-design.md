# 城迹：周末城市探索指南设计说明

日期：2026-09-15

## 1. 项目定位

“城迹”是一款面向北京大学生的移动优先周末活动探索工具。首版交付为可部署到 GitHub Pages 的高完成度前端原型，使用本地模拟数据，不接入账号、天气、地图或活动平台后端。

产品解决的核心问题是：活动信息分散，用户难以同时考虑兴趣、天气、预算和同行人数，导致周末决策成本过高。

首版成功标准：

- 首次访问者能在一个首屏内完成活动类型和预算选择。
- 提交偏好后无需跳页即可获得可理解的推荐结果。
- 用户可以完成组队、收藏、打卡和攻略发布等关键交互。
- 用户操作可在刷新后恢复，形成连贯的演示体验。
- 桌面与移动端均可完整使用，并可直接部署到 GitHub Pages。

## 2. 范围

### 2.1 包含

- 北京单城市内容。
- 活动类型与预算的首次偏好设置。
- 基于偏好、天气、预算和同行人数的本地推荐。
- 活动详情、收藏与路线查看。
- 加入或退出队伍、创建队伍。
- 创建打卡记录与查看历史。
- 浏览攻略、发布本地攻略。
- 本地持久化、明暗主题、响应式布局。
- 单元测试、组件测试和浏览器测试。

### 2.2 不包含

- 真实登录、跨设备同步和多人实时协作。
- 真实天气、地图、票务或活动平台 API。
- 在线图片上传和云端存储。
- 支付、聊天、审核、举报或消息推送。
- 北京之外的城市切换数据。

导航中的城市选择器保留扩展形态，但首版只提供北京。

## 3. 设计方向

### 3.1 设计判断

这是面向大学生的本地生活方式工具。界面应年轻、可信、直接，像一本可以操作的北京周末杂志，而不是活动聚合后台或营销落地页。

设计参数：

- `DESIGN_VARIANCE: 7`
- `MOTION_INTENSITY: 5`
- `VISUAL_DENSITY: 6`

### 3.2 视觉系统

- 默认使用冷灰纸张背景、深炭文字和荧光黄绿色单一强调色。
- 支持系统明暗主题，并提供手动主题切换。
- 图片以真实北京街区、展览、市集、演出与徒步场景为主。
- 活动图使用项目指定的文生图接口，不使用空白占位图。
- 使用现代无衬线字体，不混用装饰性衬线字体。
- 卡片和图片统一使用 8px 圆角；标签型选择控件可以使用胶囊形。
- 阴影只用于弹层和明显的层级变化，普通内容主要依靠留白和分隔线组织。
- 图标统一使用 Phosphor Icons，保持相同视觉权重。
- 页面中不使用装饰性渐变球、泛滥的状态点、超大标题或三列等宽功能卡片。

### 3.3 响应式

- 桌面端内容最大宽度约 1240px，首页首屏采用非对称双栏。
- 首访首屏左侧为标题与偏好控件，右侧为主视觉图片。
- 小于 768px 时切换为单列，图片在上、偏好控件在下。
- 桌面端使用顶部导航，移动端使用固定底部导航。
- 所有固定比例图片预留尺寸，避免布局偏移。

## 4. 信息架构

主要页面使用 Hash Router，避免 GitHub Pages 直接访问子页面时出现 404。

- `#/`：推荐首页。
- `#/teams`：组队列表与创建队伍。
- `#/checkins`：打卡记录与新建打卡。
- `#/guides`：攻略列表与发布攻略。

活动详情使用可分享的哈希子路由，例如 `#/activity/798-art-weekend`。编辑偏好使用首页内联状态，不创建独立页面。

## 5. 首页交互

### 5.1 首次访问

首页状态机为：

`onboarding -> loading -> results`

首次访问时展示：

- 品牌“城迹”和北京位置入口。
- 北京周末主视觉图片。
- 简短标题“这个周末，换条路走。”
- 活动类型多选：看展、逛市集、看演出、去徒步。
- 预算单选：免费、100 元内、100-300 元。
- “生成周末计划”按钮。

活动类型至少选择一项，预算必须选择一项。条件不完整时按钮禁用，并保留可见说明。提交后显示与最终布局一致的骨架状态，再在同一页面位置展开推荐结果。

### 5.2 推荐结果

结果页顶部保留紧凑偏好摘要，包括活动类型、预算与同行人数，并提供“调整偏好”入口。同行人数在结果态中提供单人、两人、多人快捷筛选，不增加首次访问步骤。

推荐内容顺序：

1. 周末天气摘要与选择理由。
2. 一条主推荐路线，展示总预算、预计时长、天气适配和活动节点。
3. 大小错落的备选活动网格。
4. 近期出发队伍。
5. 最近打卡与精选攻略。

“调整偏好”重新展开首页控件并保留当前值。提交新条件后替换当前结果，不追加重复内容。

### 5.3 返回访问

偏好已保存时，用户再次访问首页直接进入结果态。顶部显示当前筛选摘要，并始终保留修改入口。清除浏览器数据后恢复首次访问状态。

### 5.4 无结果

如果严格条件无匹配：

- 展示明确的空结果说明。
- 推荐放宽预算或活动类型。
- 提供“一键查看相近活动”操作。
- 不自动改变用户偏好。

## 6. 功能交互

### 6.1 活动详情

- 展示图片、时间、地点、价格、天气建议、适合人数和路线说明。
- 支持收藏、发起组队、查看已有队伍和标记完成。
- 从详情返回时保留首页滚动位置与筛选条件。

### 6.2 组队

- 队伍列表可按活动查看出发时间、集合点、人数和队长。
- 用户可加入或退出队伍，人数状态同步更新。
- 创建队伍表单包含活动、时间、集合点、人数上限和一句说明。
- 成功后弹层不立即关闭，保留明确的“已创建”状态，再由用户关闭。

### 6.3 打卡

- 用户可从已收藏或活动列表选择一个地点。
- 打卡包含日期、同行人数、评分和简短记录。
- 首版不持久化本地照片，避免 `localStorage` 容量和隐私问题。
- 保存后停留在当前表单并显示“已保存”，用户确认后再返回列表。

### 6.4 攻略

- 攻略列表支持按活动类型筛选和收藏。
- 发布表单包含标题、关联地点、正文摘要和适合人群。
- 发布内容仅保存在当前浏览器，并在攻略列表顶部标记为“我的分享”。
- 发布后停留在编辑视图并显示“已发布”，避免用户误以为内容丢失。

## 7. 推荐模型

推荐引擎实现为无副作用纯函数，输入为：

- 活动集合。
- 用户选择的活动类型。
- 预算范围。
- 当前周末天气。
- 同行人数。

排序优先级：

1. 活动类型匹配。
2. 预算不超出上限。
3. 室内外属性与天气匹配。
4. 活动建议人数与同行人数匹配。
5. 同分时按编辑推荐顺序稳定排序。

严格条件无结果时，推荐引擎返回空数组，由界面决定是否执行放宽条件的二次查询。算法本身不静默修改输入条件。

## 8. 数据与状态

静态数据按领域拆分：

- `activities`：活动基础信息、类别、价格、室内外属性、人数和图片。
- `routes`：多个活动组成的半日或一日路线。
- `weather`：周末天气示例数据。
- `teams`：已有队伍。
- `guides`：精选攻略。

本地状态包括：

- 用户偏好和是否完成首次引导。
- 收藏的活动 ID。
- 已加入和创建的队伍。
- 打卡记录。
- 用户发布的攻略。
- 主题选择。

持久化数据使用带版本号的单一命名空间。读取失败、字段缺失或版本不兼容时回退到默认值，不阻塞页面渲染。

## 9. 组件边界

- `AppShell`：桌面导航、移动底栏、主题和路由出口。
- `HomePage`：协调首页状态，不负责推荐计算细节。
- `PreferencePanel`：活动类型、预算和校验。
- `WeatherSummary`：周末天气与推荐理由。
- `RecommendationResults`：主路线和备选活动。
- `ActivityCard`：活动摘要与收藏操作。
- `ActivityDetail`：详情、组队和打卡入口。
- `TeamsPage` 与 `TeamForm`：队伍列表和创建状态。
- `CheckinsPage` 与 `CheckinForm`：打卡列表和保存状态。
- `GuidesPage` 与 `GuideComposer`：攻略浏览与发布状态。
- `recommendActivities`：纯推荐函数。
- `storageAdapter`：本地持久化和版本迁移。

页面组件不直接访问 `localStorage`，统一通过状态层与 `storageAdapter` 交互。

## 10. 动效与反馈

- 首屏内容按视觉层级轻量进入，推荐结果使用布局过渡替换偏好区域。
- 所有动效只改变 `transform` 与 `opacity`。
- 点击控件提供轻微按压反馈，保存和加入动作提供明确成功状态。
- 系统开启减少动态效果时，所有进入和布局动画退化为即时切换。
- 加载状态使用与主路线和活动网格尺寸一致的骨架，不使用通用旋转图标。

## 11. 可访问性与容错

- 所有表单控件有可见标签，键盘可操作，焦点样式清晰。
- 正文、按钮、提示和占位文字满足 WCAG AA 对比度。
- 图片包含描述活动内容的替代文本。
- 图片加载失败时显示带活动名称的中性背景，不产生布局偏移。
- 非法表单输入显示就地错误，不使用只存在数秒的提示替代错误说明。
- `localStorage` 不可用时继续提供当前会话交互，并提示数据无法长期保存。

## 12. 测试策略

### 12.1 单元测试

- 活动类型、预算、天气和人数的推荐排序。
- 同分稳定排序。
- 空结果与放宽条件查询。
- 持久化序列化、读取失败和版本回退。

### 12.2 组件测试

- 首次访问时按钮禁用与启用条件。
- 多选活动类型、单选预算和偏好编辑。
- 收藏、加入队伍、打卡保存和攻略发布反馈。
- 空状态、错误状态和图片失败状态。

### 12.3 浏览器测试

- 首次访问到推荐结果的完整路径。
- 刷新后恢复推荐结果。
- 修改偏好后推荐内容更新。
- 创建并退出队伍。
- 创建打卡并在列表中看到记录。
- 发布攻略并在列表顶部看到内容。
- 桌面和移动视口的导航、弹层与无重叠检查。
- 明暗主题和减少动态效果模式。

## 13. 部署

- 使用 Vite 生成静态产物。
- GitHub Actions 在主分支更新后运行测试和构建。
- 构建成功后发布到 GitHub Pages。
- 所有资源路径使用仓库子路径兼容配置。

## 14. 验收条件

- 首次访问首屏内可完成活动类型与预算设置。
- 推荐结果不跳页并可重新编辑。
- 天气、预算、兴趣和同行人数会实际影响排序结果。
- 组队、收藏、打卡和攻略发布均可交互并持久化。
- 页面在常见桌面和移动尺寸无横向溢出、文字遮挡或不可点击控件。
- 键盘操作、焦点状态、明暗主题和减少动态效果可用。
- 单元、组件、浏览器测试和生产构建全部通过。
- GitHub Pages 部署完成且刷新子路由可正常恢复。
